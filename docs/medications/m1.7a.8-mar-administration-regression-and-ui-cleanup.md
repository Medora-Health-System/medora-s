# M1.7A.8 — MAR administration regression & UI cleanup

**Status:** Implemented

## Root cause (POST 400)

**Exact server message (Hydromorphone, Schedule II, pharmacy pending):**

> Vérification pharmacie requise avant administration. Attendez la validation pharmacien ou documentez une dérogation motivée.

**Code:** `PHARMACY_VERIFICATION_REQUIRED` (M1.3F.7 — intentional blocking rule for Schedule II/III and selected high-alert meds).

**Why the UI looked broken:**

1. **`orderItemToMedicationSafetyGovernanceDisplay` dropped `requiresPharmacyVerification`** from enriched order items. The MAR modal hid `MarPharmacyVerificationPanel` and skipped client-side pharmacy validation, while the API still blocked administration → POST 400 with no visible workflow to satisfy.

2. **Silent client failure** — invalid `orderItemId` UUID check returned without `modalSubmitError`.

3. **MAR row clutter** — `MedicationMarSafetySummaryPanel` on every row added long governance bullet lists; concise high-alert line and badges are sufficient for operational scan.

## Blocking rules for Hydromorphone (expected)

| Rule | Blocks? | Satisfied by |
|------|---------|--------------|
| Schedule II pharmacy verify | **Yes** | Pharmacist VERIFIED or documented override (≥8 chars + ack) |
| LASA HIGH (morphine/hydromorphone) | **Yes** | LASA ack + medication selection confirmed, or override |
| High-alert double-check | **Yes** (if product profile `isHighAlert`) | Verifier or high-alert override |
| Controlled witness | **No** for Hydromorphone (`requiresWitness: false`) | — |

Informational badges (controlled, high alert, pharmacy pending) remain visible; long summary text moved behind details.

## Fixes

1. Derive/pass `requiresPharmacyVerification` in `orderItemToMedicationSafetyGovernanceDisplay`.
2. Safe `pharmacyVerification.findFirst` in `resolvePharmacyMarGovernance` when table missing.
3. PHI-safe `mar_create_validation_blocked` structured logs on governance 400s.
4. MAR UI: badges + concise high-alert warning on row; summary panel in collapsible details; modal error at top; numeric validation; no silent UUID fail.
