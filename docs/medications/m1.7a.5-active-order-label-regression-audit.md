# M1.7A.5 — Active medication order label regression audit

**Status:** Fixed in code (no migration, optional MAR snapshot backfill)

## Symptom

Active/open medication orders showed `Medication (label unavailable)` while cancelled Hydromorphone on the same encounter showed `Hydromorphone 2 mg/mL`.

## Root cause

Two coupled issues:

1. **Poisoned API display fields** — When catalog resolution failed during `enrichOrderItemsForDisplay`, `displayLabelEn` was set to the shared fallback `Medication (label unavailable)`. The web layer treated that string as a valid enriched label and returned it **before** attempting `catalogMedication` / `genericName` / INN resolution.

2. **Catalog resolution gap** — Some `OrderItem` rows store a `MedicationProduct.id` in `catalogItemId` without `medicationProductId`. Lookup by catalog id returned null, so enrichment produced fallback labels even when product + legacy catalog data existed.

**Why cancelled looked correct:** Cancelled order events often resolve titles from encounter order lines after API `lineLabelEn` is rejected as generic; active surfaces (orders summary, open orders table, MAR tasks) called `getOrderItemDisplayLabelForLanguage` and trusted bad `displayLabelEn` first.

## Affected paths

| Surface | Path |
|---------|------|
| Orders dashboard medication summary | `EmergencyErOrdersPanel.extractActiveLineLabelsForDomain` → `getOrderItemDisplayLabelForLanguage` |
| Open orders table | Same |
| MAR row / modal | `MedicationAdministrationTab.taskRows` + `marMedicationDisplayLabel` |
| API list | `OrdersService.findByEncounter` → `enrichOrderItemsForDisplaySafe` (unchanged entry; resolve fix) |

`enrichOrderItemsForDisplay` was already called for encounter orders; open orders did **not** bypass enrichment.

## Fix (M1.7A.5)

- `isOrderDisplayLabelUnavailable()` in `@medora/shared` — ignore sentinel fallback strings in UI/chart.
- `getOrderItemDisplayLabelForLanguage` / `chartSummaryOrderItemLineLabel` — re-resolve from catalog when API label is unavailable.
- `loadOrderMedicationCatalogMaps` / `resolveOrderMedicationCatalogRow` — treat `catalogItemId` as product id when catalog id miss.
- MAR — prefer live order-line label when `medicationLabelSnapshot` is unavailable text.

### Read-only audit SQL

Replace `:order_item_id_active` and `:order_item_id_cancelled` with your Hydromorphone line ids.

```sql
-- Active vs cancelled OrderItem linkage (same encounter)
SELECT
  oi.id,
  oi."catalogItemId",
  oi."medicationProductId",
  oi."catalogItemType",
  oi.strength,
  oi."manualLabel",
  o.status AS order_status,
  cm.code AS catalog_code,
  cm."genericName",
  cm."displayNameEn",
  cm."displayNameFr",
  mp.code AS product_code,
  mp."strengthDisplay",
  mp."legacyCatalogMedicationId"
FROM "OrderItem" oi
JOIN "Order" o ON o.id = oi."orderId"
LEFT JOIN "CatalogMedication" cm ON cm.id = oi."catalogItemId"
LEFT JOIN "MedicationProduct" mp ON mp.id = oi."catalogItemId"
   OR mp.id = oi."medicationProductId"
WHERE oi.id IN (:order_item_id_active, :order_item_id_cancelled)
ORDER BY o.status, oi."createdAt";

-- MAR snapshots that may need optional backfill
SELECT id, "orderItemId", "medicationLabelSnapshot", "administeredAt"
FROM "MedicationAdministration"
WHERE "orderItemId" = :order_item_id_active
  AND ("medicationLabelSnapshot" ILIKE '%label unavailable%'
    OR "medicationLabelSnapshot" ILIKE '%libellé indisponible%');
```
