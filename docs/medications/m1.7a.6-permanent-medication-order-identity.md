# M1.7A.6 — Permanent medication order identity

**Status:** Implemented (no migration)

## Symptom (post M1.7A.5)

Active Hydromorphone orders showed **`2 mg/mL`** only (orders table, MAR). Cancelled Hydromorphone on the same encounter still showed **`Hydromorphone 2 mg/mL`**.

## Root cause (proven)

1. **Strength-only fallback in MAR snapshot builder** — `buildMedicationOrderLabelSnapshot` returned `it.strength` when catalog primary name resolution failed (`fromRow` path). Existing MAR rows could store **`2 mg/mL`** as `medicationLabelSnapshot`.

2. **Poisoned catalog display fields** — Some active `OrderItem` rows linked via `MedicationProduct.id` in `catalogItemId` expose legacy `CatalogMedication` rows where `displayNameEn` / `displayNameFr` were set to **`2 mg/mL`** (strength copied into name fields). M1.7A.5 ignored “label unavailable” but still trusted strength-shaped “names”.

3. **Web/API trusted incomplete enriched labels** — `displayLabelEn` / `displayLabelFr` or client catalog detail lines could be **strength-only**; `getOrderItemDisplayLabelForLanguage` returned them before re-resolving identity from `genericName`, product concept, or catalog code INN.

**Why cancelled looked correct:** Cancelled lines often had full `genericName` on catalog rows or event titles built before the strength-only poison path; active open-order and MAR paths hit snapshot + poisoned `displayLabelEn` first.

## Fix

### Shared contract — `resolveMedicationOrderIdentity`

Module: `packages/shared/src/medication/medicationOrderIdentity.ts`

Output:

```ts
{
  medicationNameEn,
  medicationNameFr,
  strengthDisplay,
  displayLabelEn,  // name + strength
  displayLabelFr,
  source,
  confidence,
}
```

**Critical rule:** strength alone is never a valid medication name or display label (`isStrengthOnlyMedicationLabel`, `isIncompleteMedicationOrderDisplayLabel`).

Source priority: catalog display names → genericName → product legacy catalog → MedicationConcept → code INN → snapshot (name part) → manual → fallback.

### Wired through

- `buildOrderItemDisplayLabelEn` / `Fr` (API enrichment)
- `buildMedicationOrderLabelSnapshot` (MAR create + audit)
- Web `getOrderItemDisplayLabelForLanguage`, chart summary labels
- MAR `marMedicationDisplayLabel` — rejects incomplete snapshots, prefers live order line

## SQL audit (read-only)

Replace ids for your encounter:

```sql
SELECT
  o.id AS order_id,
  o.status AS order_status,
  oi.id AS order_item_id,
  oi."catalogItemId",
  oi."medicationProductId",
  oi."catalogItemType",
  oi.strength,
  oi."manualLabel",
  cm.id AS catalog_id,
  cm.code AS catalog_code,
  cm."genericName",
  cm."displayNameEn",
  cm."displayNameFr",
  cm.strength AS catalog_strength,
  mp.id AS product_id,
  mp.code AS product_code,
  mp."strengthDisplay",
  mp."legacyCatalogMedicationId",
  mc."genericName" AS concept_generic,
  mc."displayName" AS concept_display
FROM "OrderItem" oi
JOIN "Order" o ON o.id = oi."orderId"
LEFT JOIN "CatalogMedication" cm ON cm.id = oi."catalogItemId"
LEFT JOIN "MedicationProduct" mp
  ON mp.id = oi."medicationProductId" OR mp.id = oi."catalogItemId"
LEFT JOIN "MedicationConcept" mc ON mc.id = mp."conceptId"
WHERE oi."catalogItemType" = 'MEDICATION'
  AND (mp.code ILIKE '%HYDROMORPHONE%' OR cm.code ILIKE '%HYDROMORPHONE%')
ORDER BY o.status, oi."createdAt";

SELECT
  ma.id,
  ma."orderItemId",
  ma."medicationLabelSnapshot",
  ma."administeredAt"
FROM "MedicationAdministration" ma
JOIN "OrderItem" oi ON oi.id = ma."orderItemId"
WHERE ma."medicationLabelSnapshot" ~ '^[0-9]'
   OR ma."medicationLabelSnapshot" ILIKE '%label unavailable%';
```

| Item | Required |
|------|----------|
| Migration | **NO** |
| Seed | **NO** |
| SQL update | **Optional** — only `MedicationAdministration.medicationLabelSnapshot` that is strength-only; UI now prefers live order label. OrderItem rows need no column backfill. |

Optional snapshot repair (manual review):

```sql
-- Audit only — do not run UPDATE without clinical review
SELECT ma.id, ma."medicationLabelSnapshot", oi.strength, cm."genericName", cm.code
FROM "MedicationAdministration" ma
JOIN "OrderItem" oi ON oi.id = ma."orderItemId"
LEFT JOIN "CatalogMedication" cm ON cm.id = oi."catalogItemId"
WHERE ma."medicationLabelSnapshot" = oi.strength;
```
