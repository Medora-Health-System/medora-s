# M1.7A.7 — Order enrichment fail-closed medication label fix

**Status:** Implemented

## Railway production error

```
[Nest] WARN [OrdersService] event="enrich_order_items_failed_fallback_labels"
Invalid prisma.pharmacyVerification.findMany() invocation:
The table `public.PharmacyVerification` does not exist in the current database.
```

## Root cause

1. `enrichOrderItemsForDisplay` ran **required** label enrichment and **optional** pharmacy verification in a single `Promise.all`.
2. When `pharmacyVerification.findMany()` failed (table not deployed), the entire enrichment threw.
3. `enrichOrderItemsForDisplaySafe` caught the error and called `enrichOrderItemsWithCatalogFallback`, which set `catalogMedication: null` and rebuilt labels **without catalog identity** → `Medication (label unavailable)` or strength-only `2 mg/mL`.

Medication identity (CatalogMedication / MedicationProduct / concept) was already available but never applied because optional pharmacy verification failed first.

## Fix

### Required vs optional enrichment

| Stage | Required | On failure |
|-------|----------|------------|
| Medication catalog/product maps | Yes | throw (safe wrapper tries catalog in fallback) |
| Lab / imaging catalog | Yes | throw |
| Display labels (M1.7A.6 resolver) | Yes | throw |
| Pharmacy verification | **Optional** | log + empty map |
| Medication safety governance | **Optional** | log + empty map |

### Safe loaders

- `loadLatestPharmacyVerificationByOrderItemIdSafe`
- `loadPharmacyVerificationDetailsByOrderItemIdSafe`
- `loadMedicationSafetyGovernanceByCatalogIdSafe`

On missing table (`P2021` / `P2022` or message match):

```
event="pharmacy_verification_enrichment_skipped"
reason="table_missing"
```

Enrichment continues; `displayLabelEn` / `displayLabelFr` still resolve via M1.7A.6 identity contract.

### Improved fallback

`enrichOrderItemsWithCatalogFallback` now attempts `loadOrderMedicationCatalogMaps` + `resolveOrderMedicationCatalogRow` so even unexpected required-path failures preserve medication name when catalog data exists.

## Schema / migration audit

`PharmacyVerification` is defined in Prisma schema and migration:

- `apps/api/prisma/schema.prisma` — model `PharmacyVerification`
- `apps/api/prisma/migrations/20260903120000_m1_3f1_mar_emar_schema_foundation/migration.sql` — `CREATE TABLE "PharmacyVerification"`

**Finding:** Production Railway DB has **migration drift** — MAR eMAR foundation migration not applied. This is **not** a model name mismatch; the table was never deployed.

### Migration deploy (Railway / production)

```bash
pnpm --filter @medora/api exec prisma migrate deploy
```

**Migration deploy required:** **YES** (for pharmacy verification features; labels work without it after M1.7A.7)

### SQL audit (read-only)

```sql
SELECT EXISTS (
  SELECT 1
  FROM information_schema.tables
  WHERE table_schema = 'public'
    AND table_name = 'PharmacyVerification'
) AS pharmacy_verification_table_exists;

SELECT migration_name, finished_at
FROM "_prisma_migrations"
WHERE migration_name LIKE '%mar_emar%'
ORDER BY finished_at DESC;
```
