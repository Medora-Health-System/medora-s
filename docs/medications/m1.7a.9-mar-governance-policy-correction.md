# M1.7A.9 — MAR governance policy correction

**Status:** Implemented

## Policy change

Bedside MAR administration no longer blocks on pharmacy verification. Double-check is narrowed to a short allowlist.

### Pharmacy verification (MAR)

| Before (M1.3F.7 / M1.7A.8) | After (M1.7A.9) |
|----------------------------|-----------------|
| Schedule II/III and selected high-alert meds blocked MAR until pharmacist verified or override | **Informational only** at MAR — no POST block, no blocking modal panel |
| `PHARMACY_VERIFICATION_REQUIRED` 400 | Never returned for MAR create |

Pharmacy worklist / verification records remain for pharmacist workflow; they do not gate nurse administration.

### Double-check (MAR)

| Medication context | Double-check required? |
|--------------------|------------------------|
| Hydromorphone / opioid IV push (one-time) | **No** — high-alert + controlled badges/warnings only |
| Insulin | **Yes** |
| Heparin (`HIGH_ALERT_ANTICOAGULANT`) | **Yes** |
| Blood products (catalog code heuristics) | **Yes** |
| PCA/PCP opioid pump route | **Yes** |
| Continuous opioid infusion pump | **Yes** |

## Implementation

Central policy: `packages/shared/src/medication/marAdministrationGovernancePolicy.ts`

- `marPharmacyVerificationBlocksAdministration()` → `false`
- `marAdministrationRequiresDoubleCheck()` → allowlist logic
- `validatePharmacyMarCreate()` → always `{ ok: true }` when blocking disabled
- `highAlertMarRequiresDoubleCheck()` delegates to policy

API resolves continuous-infusion context before high-alert governance (`medication-administration.service.ts`).

Web MAR display derives `requiresDoubleSign` from policy, not raw catalog flag.

## Hydromorphone expected behavior

- Row: **Hydromorphone 2 mg/mL**, high-alert warning, controlled badge
- Modal: LASA ack if applicable; **no** pharmacy panel; **no** double-check fields
- POST succeeds with normal MAR fields + LASA when required
